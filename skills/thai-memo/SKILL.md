# บันทึกข้อความ (.docx)

ร่างเนื้อหาตามแบบงานสารบรรณ แล้วให้ `scripts/build_memo.py` สร้าง .docx ที่หน้าตาเหมือน
บันทึกข้อความที่โรงพยาบาลใช้จริง: ตราครุฑ, หัวกระดาษเส้นประ, ขอบซ้าย 3 ซม. ขวา 2 ซม.,
ย่อหน้า 2.5 ซม., เลขหน้า "- ๒ -" ตั้งแต่หน้า 2 สคริปต์ใช้ Python stdlib อย่างเดียว

## เอกสาร 3 แบบที่เจอบ่อย

| แบบ | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| **ขออนุมัติ / ขอลงนาม ฉบับเดียว** | กลุ่มงานเสนอ ผอ. ให้อนุมัติหรือลงนามในเอกสารที่แนบ (ข้อตกลง สัญญา ฯลฯ) | `examples/approval.json` |
| **หนังสือออก** | รพ. มีหนังสือถึงหน่วยงานอื่นในสังกัด (เช่น นพ.สสจ.) ผอ. ลงนาม อาจมีสิ่งที่ส่งมาด้วย | `examples/letter.json` |
| **คู่ หนังสือออก + ใบเสนอ ผอ.** | หนังสือออกที่ต้องให้ ผอ. เซ็น — ทำ 2 ไฟล์: ตัวหนังสือ และใบเสนอที่สรุปหนังสือนั้นพร้อมช่องความเห็น/คำสั่ง ผอ. | `letter.json` + `examples/cover.json` |

ถามผู้ใช้ว่าเป็นแบบไหนถ้าดูจากคำขอแล้วไม่ชัด ถ้าเป็นแบบคู่ ร่างตัวหนังสือออกก่อน
แล้วค่อยย่อเนื้อหาเป็นใบเสนอ ทั้งสองฉบับต้องอ้างเรื่อง จำนวนสิ่งที่ส่งมาด้วย และคำขอตรงกัน

หนังสือภายนอก (ตราครุฑ 3 ซม. มี "ขอแสดงความนับถือ") ใช้รูปแบบอื่น สคริปต์นี้ทำไม่ได้
ให้บอกผู้ใช้ตรง ๆ

## ค่าประจำหน่วยงาน — `~/.claude/thai-memo.json`

ชื่อคน ตำแหน่ง และเบอร์โทรเก็บไว้ในเครื่อง **ไม่ใส่ใน repo นี้** (repo เป็น public) อ่านไฟล์นี้ก่อนร่างทุกครั้ง
ถ้าไม่มีไฟล์ ให้ถามผู้ใช้ครั้งเดียว (หรือดึงจากบันทึกข้อความเดิมที่ผู้ใช้ส่งมา) แล้วบันทึกไว้:

```json
{
  "agency": "กลุ่มงานสุขภาพดิจิทัล  โรงพยาบาลแพร่  โทร. ๘๑๓๗, ๘๘๘๘",
  "ref_prefix": "พร ๐๐๓๓.๒๕๙.๑/",
  "signer": { "name": "(นาย...)", "position": "รองผู้อำนวยการฝ่าย..." },
  "director": { "name": "(นาง...)", "position": "ผู้อำนวยการโรงพยาบาล..." },
  "output_dir": "C:/Users/<user>/Downloads"
}
```

ค่าในไฟล์เป็นค่าเริ่มต้น ถ้าผู้ใช้บอกค่าอื่นในงานไหน ให้ใช้ค่านั้นในงานนั้น ถ้าบอกว่าเปลี่ยนถาวร
(เช่น ย้ายตำแหน่ง หรือเปลี่ยนเบอร์) ค่อยแก้ไฟล์

## 1. เก็บข้อมูลก่อนร่าง

ถามเฉพาะสิ่งที่ยังขาด ข้อมูลที่ต้องมี:

- **เรื่อง** และ **เรียน** ใคร
- **เหตุ** คืออ้างถึงอะไร (นโยบาย สัญญาเลขที่ หนังสือเลขที่) พร้อมวันที่
- **ความประสงค์** คือขออะไร เป็นข้อ ๆ ถ้ามีหลายข้อ
- **สิ่งที่ส่งมาด้วย** ว่ามีกี่รายการ แต่ละรายการคืออะไร ต้องแนบเป็นหน้าในไฟล์ หรือเป็นเอกสารแยก
- ผู้ประสานงาน / ช่องทางติดต่อ ถ้าหนังสือต้องมี

ห้ามแต่งข้อเท็จจริงขึ้นเอง เช่น เลขที่สัญญา วันที่ จำนวน ชื่อบริษัท ถ้ายังไม่รู้ ให้ใส่ `[ ]` ไว้
แล้วบอกผู้ใช้ว่ามีจุดที่ต้องเติม

## 2. ร่างเนื้อหา

โครงข้อความ 3 ภาค แต่ละภาคเป็นย่อหน้าละ 1 ย่อหน้า ยาวได้หลายบรรทัด:

1. **ภาคเหตุ** — "ด้วย..." (เรื่องใหม่) หรือ "ตาม... นั้น" (อ้างเรื่องเดิม) ถ้าจะต่อด้วยเรื่องปัจจุบันใช้ "บัดนี้..."
2. **ภาคความประสงค์** — สิ่งที่ทำไปแล้วและสิ่งที่ขอ ถ้าขอหลายอย่างให้แตกเป็นข้อ ๑. ๒. ๓.
   ปิดด้วย "ทั้งนี้ ..." สำหรับเงื่อนไขหรือข้อผูกพัน เช่น ใช้ข้อมูลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล
   หรือไม่มีค่าใช้จ่ายเพิ่ม
3. **ภาคสรุป** — ขึ้นต้น "จึงเรียนมาเพื่อ..." เลือกตามสิ่งที่ขอ:
   - `จึงเรียนมาเพื่อโปรดทราบ`
   - `จึงเรียนมาเพื่อโปรดพิจารณาอนุมัติ`
   - `จึงเรียนมาเพื่อโปรดพิจารณา หากเห็นชอบโปรดลงนามใน... จำนวน ... ฉบับ ที่แนบมาพร้อมนี้`
   - `จึงเรียนมาเพื่อโปรดพิจารณาให้ความอนุเคราะห์... ต่อไป`

ใบเสนอ ผอ. ของแบบคู่: ย่อเหตุเหลือ 1–2 ย่อหน้า ต่อด้วย "กลุ่มงาน...ได้จัดทำร่างหนังสือถึง... เพื่อ..."
แล้วสรุปคำขอในหนังสือเป็น (๑) (๒) (๓) ในย่อหน้าเดียว ปิดด้วย
"หากเห็นชอบโปรดลงนามในหนังสือถึง... พร้อมสิ่งที่ส่งมาด้วย N รายการ ที่แนบมาพร้อมนี้"

ภาษาและตัวเลข:
- ใช้ภาษาราชการ สั้น ตรง ไม่ใช้ภาษาพูด
- ตัวเลขในเนื้อความเป็นเลขไทย (๒๕๖๙, ๑๔ หอผู้ป่วย) ส่วนชื่อเฉพาะภาษาอังกฤษพิมพ์ตามจริง (API, Dashboard)
- **ที่** ใส่แค่รหัสหน่วยงานกับ "/" และ **วันที่** ใส่แค่เดือนกับปี เว้นเลขที่กับวันไว้ให้งานสารบรรณลงเอง
  เว้นแต่ผู้ใช้ให้เลขมาแล้ว
- ห้ามมีข้อมูลระบุตัวผู้ป่วย (HN, ชื่อ-สกุล, เลขบัตรประชาชน) ในหนังสือเด็ดขาด

## 3. เขียน spec แล้ว build

เขียน spec เป็น JSON (UTF-8) ไว้ใน scratchpad แล้วรัน:

```
python -X utf8 <skill-dir>/scripts/build_memo.py <spec.json> [<out.docx>]
```

ถ้าไม่ระบุ out จะใช้ `output` ใน spec บันทึกลง `output_dir` ของผู้ใช้ และตั้งชื่อไฟล์แบบเดียวกับที่ผู้ใช้ตั้ง
เช่น `บันทึกข้อความ <เรื่องย่อ>.docx` / `บันทึกข้อความ เสนอ ผอ. <เรื่องย่อ>.docx`

| key | ความหมาย |
|---|---|
| `agency`, `ref_no`, `date`, `subject`, `to` | หัวบันทึก (ส่วนราชการ / ที่ / วันที่ / เรื่อง / เรียน) |
| `body` | รายการ block ของเนื้อความ |
| `signer` | `{name, position}` ผู้ลงนามท้ายบันทึก (`position` เป็น string หรือ list หลายบรรทัดได้) |
| `after_signature` | block ใต้ลายเซ็น เช่น QR code หรือช่องทางติดต่อ |
| `approval` | ช่องความเห็น/คำสั่ง ผอ.: `{title, options[], name, position}` |
| `attachments` | สิ่งที่ส่งมาด้วย หน้าใหม่ ไม่มีเลขหน้า: `[{title: [บรรทัด...], body: [block...]}]` |

block ใน `body` / `attachments[].body` / `after_signature`:

| block | ผลลัพธ์ |
|---|---|
| `"ข้อความ"` | ย่อหน้าปกติ เยื้อง 2.5 ซม. ชิดสองข้าง (ใส่ `{"type":"para","text":...,"indent":false}` ถ้าไม่เยื้อง) |
| `{"type":"heading","text"}` | หัวข้อตัวหนา ใช้ในสิ่งที่ส่งมาด้วย |
| `{"type":"list","style","items","start"}` | รายการแบบเยื้องแขวน `style` เป็น `number` (๑.), `paren` ((๑)), `bullet` (•) หรือ `dash` (-) ข้อย่อยใช้ `{"text", "items":[...]}` และ `start` ใช้นับเลขข้อต่อหลังตารางที่คั่นกลาง |
| `{"type":"table","rows","widths","align","indent"}` | ตารางเส้นทึบ แถวแรกเป็นหัวตารางพื้นเทา `widths` คือสัดส่วนความกว้าง `indent:true` เยื้องให้ตรงข้อความของข้อ ๑. |
| `{"type":"code","text"}` | กล่องพื้นเทา ใช้กับตัวอย่าง JSON หรือคำสั่ง |
| `{"type":"image","path","width_cm","caption"}` | รูป PNG เช่น QR code (path อ้างจากโฟลเดอร์ของ spec) |

ในข้อความใช้ `**ตัวหนา**` และ `` `รหัส` `` ได้

**กับดักเลขไทย:** TH SarabunIT๙ วาดเลข 0–9 เป็นเลขไทยทั้งหมด รหัสที่คนต้องพิมพ์ตาม (รหัสเชิญ, URL,
เลข ID, ค่าตัวอย่าง JSON) จึงต้องอยู่ใน `` `...` `` ซึ่งจะเปลี่ยนไปใช้ TH SarabunPSK และแสดงเลขอารบิก
ถ้าไม่ครอบไว้ `282B-M3MZ` จะพิมพ์ออกมาเป็น `๒๘๒B-M๓MZ`

## 4. ตรวจก่อนส่ง

แปลงเป็น PDF แล้วเปิดดูทุกหน้า:

```
"C:/Program Files/LibreOffice/program/soffice.exe" --headless --convert-to pdf --outdir <dir> <file.docx>
```

สิ่งที่ต้องเช็ก:
- ใบเสนอ ผอ. ควรจบในหน้าเดียว ถ้าล้นให้ย่อเนื้อความ อย่าลดขนาดฟอนต์
- บล็อกลายเซ็นกับช่องความเห็น ผอ. ต้องไม่ถูกตัดข้ามหน้า สคริปต์ล็อกไว้แล้ว ถ้าช่องว่างไม่พอ บล็อกจะย้ายไปหน้าถัดไปทั้งก้อน
- รหัสหรือ URL ต้องเป็นเลขอารบิก
- เลขที่ เรื่อง และจำนวนสิ่งที่ส่งมาด้วยตรงกันทุกไฟล์ (กรณีแบบคู่)

ถ้าหนังสือยาวเกินหน้า งานสารบรรณจะเขียนคำต่อเนื่อง "/ข้อความ..." ไว้มุมขวาล่าง สคริปต์ใส่ให้ไม่ได้
เพราะไม่รู้ว่าหน้าจะตัดตรงไหน ให้บอกผู้ใช้ให้เติมใน Word ก่อนพิมพ์

ส่งงานโดยบอก path ของไฟล์ .docx (และ PDF ถ้าทำ) สรุปเนื้อหาสั้น ๆ และแจ้งจุด `[ ]`
ที่ผู้ใช้ต้องเติมเอง
